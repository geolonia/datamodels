# 調達仕様に書く一行

自民党デジタル社会推進本部の防災DX の提言（2026年5月）は、自治体に、次のシステム更新で調達仕様に「相互運用性、標準準拠、データのポータビリティ（移出性）」を要件として加えるよう求めています。これがなければベンダーロックインは避けられない、という考えです（[大野敬太郎氏へのインタビュー、デジタル行政、2026年9月29日](https://www.digital-gyosei.com/post/2026-09-29-interview-keitaroohno-part2/)）。

このページは、このカタログのモデルと対応表を使ってその要件を書くときの文例と、提案を確かめる方法をまとめたものです。

::: info 文例について
文例は出発点で、そのまま使える法的な文言ではありません。自団体の契約の形、既存のシステム、調達の規則に合わせて直してください。
:::

## 文例

扱うデータに合わせて、[データモデル一覧](/models/)から型を選び、文中の型名を置き換えます。以下は避難所・避難場所の例です。

**標準準拠**

> 本システムが保有する避難所・避難場所のデータは、datamodels.jp の DesignatedShelter、EvacuationSite 及び EvacuationShelter の各モデル（JSON Schema、CC0 1.0）に適合する JSON で出力できること。施設の識別には全国共通避難所・避難場所ID を用いること。

**相互運用性**

> データの出力及び入力は、公開された仕様に基づく API（NGSI-LD API 等）又はファイルで行えること。受注者は、本システムのデータ項目と上記モデル及び災害対応基本共有情報（EEI）との対応表を納品物に含めること。

**データの移出性**

> 本システムが保有するデータの権利は発注者に帰属し、発注者は、契約期間中及び契約終了時に、追加の費用なく全件を上記の形式で取り出せること。

## 提案を確かめる

- **対応表**: 提案者に、システムのデータ項目とモデルの属性の対応を示してもらいます。各モデルのページにある「対応する標準」の表と同じ形で足ります。どの標準にどのモデルが対応しているかは[対応する標準](/models/standards/)の一覧にあります。
- **見本のデータ**: 出力した JSON を、モデルの JSON Schema で検証します（[使い方](/guide/use)の手順 2）。エラーが出なければ、形式は合っています。
- **費用**: データの出力や API の利用に別の費用がかからないか、契約書と見積りで確かめます。

## モデルに足りない項目があるとき

必要な項目がモデルに無いときは、[拡張する](/guide/extend)で自団体の属性を足すか、[貢献する](/guide/contribute)からカタログへの追加を提案してください。
