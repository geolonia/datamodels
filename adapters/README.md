# Adapters

The catalog itself (contexts, schemas, examples, vocabularies, pages) is independent of any product. An adapter turns catalog models into files a particular broker or tool consumes, and is published next to the catalog under `/adapters/<name>/`.

Rules:

- The core (`scripts/`, `models/`) never imports from `adapters/`. `scripts/lib/adapters.mjs` discovers every `adapters/<name>/index.mjs`, for the build and for `npm run site:dev`.
- An adapter only adds files. It cannot change a context, a schema or an IRI.
- Adapter output is generated on every build and is not part of the immutability manifest; pin the catalog version, not an adapter file.
- Model pages stay product-neutral: they do not name a product or link a product's file. The files of a generic adapter (`download: true`, no product) are buttons in the model page's "Download" row, which links their explanation on `/adapters/` (`#downloads`). A model that a product adapter serves gets an "Adapters" sentence linking the products' part of `/adapters/` (`#products`).
- `/adapters/` explains each adapter in its own section (`#<name>`): what the file is (`note`), how to use it (`use`), where to get it (the Download row or the list by model, `catalog.json`, `command`) and one example file. It does not list the files by model, so it does not grow with the catalog. Only a product adapter gets a list by model, at `/adapters/<name>/`; the old lists of the generic adapters redirect to their sections (`public/_redirects`). Both pages are generated by `scripts/lib/adapter-pages.mjs`.
- `catalog.json` lists every adapter's files per model under `adapters`, and a product's guide page is listed in the Guides under "Using the models" (the sidebar in `site/.vitepress/config.ts` and `site/guide/index.md`).

Interface of `index.mjs` (default export):

| Member | Meaning |
|---|---|
| `name` | directory name and URL segment |
| `label` | `{ ja, en }` human-readable name of the adapter |
| `note` | optional `{ ja, en }` one-line explanation of the file |
| `guide` | optional site path of the adapter's guide page |
| `use` | optional `{ ja, en }` how to use the file (Markdown; links carry their language, `/en/...`) |
| `command` | optional command that makes the file yourself |
| `download` | optional `true` for a generic file (no product): model pages show it as a button in their "Download" row, and it gets no list by model |
| `urlFor(subject, model)` | absolute URL of the file for this model, or `null` |
| `content(subject, model)` | file content for that URL |

Adapters today:

- [`csv`](csv/), [`table-schema`](table-schema/), [`ai`](ai/) and [`postgis`](postgis/): the adapters of [datamodels-toolkit](https://github.com/geolonia/datamodels-toolkit) (`@geolonia/datamodels/adapters`, a devDependency pinned to a release tag). A CSV template, its Table Schema, a strict JSON Schema for the structured output of AI models, and a PostgreSQL / PostGIS `CREATE TABLE`. [`toolkit.mjs`](toolkit.mjs) gives them their third argument, `context`: this catalog's URL builders, its languages, and the schemas their `$ref`s name, read from `models/` without the network. They are generic, so model pages have them as buttons under "Download"; the guide is `/toolkit/export`.
- [`geonicdb`](geonicdb/): GeonicDB Custom Data Model bodies and the `export.mjs` CLI for tenant-specific variants. A product's files, so only on `/adapters/` and its list by model, `/adapters/geonicdb/`.
